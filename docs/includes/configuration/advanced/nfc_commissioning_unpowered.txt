NFC-based commissioning in unpowered mode
-----------------------------------------

.. toggle::

    In ``unpowered mode``, you can write commissioning data to an external NFC tag while the nRF SoC is powered off.
    When the SoC boots, the application reads that data from the tag and attempts to join the Matter fabric stored on the tag.
    This lets you prepare a device for a specific fabric even when a commissioner is not in radio range at boot time.

    An nRF SoC cannot implement this use case with the on-chip NFCT peripheral alone.
    Connect an external NFC tag that acts as a secure element and stores the commissioning material for the application to use during startup.

    The |addon| supports the following external NFC tag modules:

    * `ST25DA-C`_

    The table below lists the pin connections for each supported module on the nRF DK targets:

    To enable NFC-based commissioning in ``unpowered mode``, connect the ST25DA-C module to your nRF DK as shown in the table and build the application with the ``st_25_dac`` shield and the following Kconfig options.

    Required Kconfig options:

    * :kconfig:option:`CONFIG_CHIP_NFC_BASED_COMMISSIONING` - Set to ``y`` to enable Matter NFC-based commissioning.
    * :kconfig:option:`CONFIG_CHIP_NFC_COMMISSIONING_MODE_UNPOWERED` - Set to ``y`` to enable unpowered mode.

    Attaching the ``st_25_dac`` shield enables :kconfig:option:`CONFIG_ST25DAC`, which builds the ST25DA-C driver and selects :kconfig:option:`CONFIG_MATTER_NFC_COMMISSIONING_BACKEND_ST25DAC` as the tag backend.

    Optional Kconfig options:

    * :kconfig:option:`CONFIG_MATTER_NFC_COMMISSIONING_BUTTON_TRIGGER` - Powers the ST25DA-C and starts commissioning when you press the configured button on a Nordic DK (enabled by default).
    * :kconfig:option:`CONFIG_MATTER_NFC_COMMISSIONING_SHELL` - Registers the ``nfc`` Zephyr shell command for backend-specific commissioning operations.
    * :kconfig:option:`CONFIG_MATTER_NFC_COMMISSIONING_ONBOARDING_RENDEZVOUS_BLE_AND_NFC` - Sets both Bluetooth LE and NFC commissioning flags in the onboarding rendezvous data.
    * :kconfig:option:`CONFIG_ST25DAC_FW_UPDATE` - Includes ST25DA-C firmware update support.
    * :kconfig:option:`CONFIG_CHIP_NFC_BASED_COMMISSIONING_APDU_DEBUG` - Enables additional debug logging of ISO-DEP APDU traffic.

    Build a |matter_type| with unpowered NFC commissioning support as follows:

    .. tabs::

       .. group-tab:: |nRFVSC|

          Add the following options to :guilabel:`Extra CMake arguments` in your build configuration:

          * ``-DSHIELD=st_25_dac``
          * ``-DCONFIG_CHIP_NFC_BASED_COMMISSIONING=y``
          * ``-DCONFIG_CHIP_NFC_COMMISSIONING_MODE_UNPOWERED=y``

       .. group-tab:: Command line

          .. code-block:: console

             west build -p -b <board_target> -- -DSHIELD=st_25_dac -DCONFIG_CHIP_NFC_BASED_COMMISSIONING=y -DCONFIG_CHIP_NFC_COMMISSIONING_MODE_UNPOWERED=y

    Replace ``<board_target>`` with a supported board target, for example ``nrf52840dk/nrf52840``.

    After flashing, the application reads commissioning data from the tag during boot (or when triggered by the button, if enabled) and attempts to join the Matter fabric stored on the tag.

    To learn more about the unpowered NFC commissioning, see the :ref:`ug_matter_configuring_optional_nfc_unpowered` user guide.
